# 연말 대항전

참가자 전원이 각자 폰으로 동시에 겨루는 송년회 조 대항 미니게임입니다. 17종 게임을 관리자가 골라 진행합니다.

## 구성

Next.js 정적 빌드(`out/`)를 Cloudflare Worker가 제공하고, 방 하나를 Durable Object 하나가 처리합니다. 별도 DB는 쓰지 않습니다. 점수와 참가자는 Durable Object 저장소에 저장되어 재접속·재시작에도 유지되고, 방을 닫으면 지워집니다.

행사장 전광판의 탭은 관리자가 원격으로 바꾸거나 화면에서 직접 누를 수 있습니다. 게임이 시작되면 진행 탭으로 돌아오고, 게임 중에는 바뀌지 않습니다.

## 방 종료

- 관리자 조작·입장·게임 입력이 일정 시간 없으면 방을 닫습니다. 게임 기록이 없는 방은 `ROOM_IDLE_MINUTES`(10분), 있는 방은 `ROOM_PLAYED_IDLE_MINUTES`(60분)이고 `wrangler.jsonc`에서 바꿉니다. 화면을 켜 두기만 한 것은 사용으로 치지 않습니다. 대시보드의 **닫기**로 바로 닫을 수도 있습니다.
- 방이 닫히면 통계·개인 순위·상품 후보도 삭제됩니다. 상품 확인은 그 전에 합니다.
- 서버는 요청이 있을 때만 실행됩니다. 닫힌 방의 화면은 재접속하지 않고, 연결 실패가 20번 이어지면 멈춘 뒤 다시 연결 버튼을 보여 줍니다. 대시보드 자동 갱신은 탭을 볼 때만 돌고 15분 뒤 멈춥니다.

| 사용자 | 주소 | 역할 |
|---|---|---|
| 인트로 | `/` | 네온 환영 문구, 흐르는 감사 인사, 입장 가능한 방의 QR. 문구는 `games.json`의 `intro`에서 수정 |
| 관리자 | `/backstage` → `/backstage/?room=코드` | 방 목록·생성, 탭 4개(진행·참가자·통계·설정), 행사장 화면 열기, 점수 초기화 |
| 행사장 전광판 | `/screen/?room=코드&key=화면키` | 탭 2개. 진행: QR·게임 목록·규칙·게임 현황·라운드 1등·최종 발표. 순위: 조 순위·개인 TOP 10 |
| 참가자 | `/play/?room=코드` | 입장 코드 → 조 선택 → 이름·닉네임 → 게임 |

다른 기기에서 관리자 화면을 열려면 대시보드에 로그인한 뒤 해당 방의 **관리**를 누릅니다. 대시보드 비밀번호는 저장하지 않으므로 새로고침하면 다시 입력합니다.

관리 기능은 게임 방의 실시간 상태를 직접 다루므로 별도 앱으로 나누지 않고 같은 애플리케이션에서 주소만 나눕니다.

## 폴더

- `src/content/games.json`: 게임 이름·규칙·시간 등 콘텐츠
- `src/game/engine.ts`: 서버와 폰이 함께 쓰는 게임 규칙·순위 계산
- `src/game/protocol.ts`: WebSocket 메시지 형식
- `worker/room.ts`: 방 상태를 관리하는 Durable Object
- `worker/registry.ts`: 대시보드용 방 목록 Durable Object
- `src/components/`: 관리자·행사장·참가자 화면
- `scripts/simulate.mjs`: 참가자 봇 검증 도구

## 진행 방식과 점수

- 방 설정에서 **조 대항전** 또는 **개인전**을 고릅니다. 참가자가 입장한 뒤에는 바꿀 수 없습니다.
- 같은 게임을 여러 번 할 수 있습니다. 라운드마다 새 문제가 나옵니다. 결과 화면의 **같은 게임 다시**로 바로 고를 수 있고, 최종 발표 뒤에도 **게임 더 하기**로 이어 갈 수 있습니다. 점수는 유지됩니다.
- 두 방식 모두 개인 누적 순위가 있습니다. 라운드마다 개인 점수(0~100)를 더합니다. 전광판에는 닉네임 TOP 10이, 관리자 화면에는 실명을 포함한 전체 순위와 조별 1등, 상품 후보 표시가 나옵니다.

조 대항전의 조 점수는 다음과 같이 계산합니다.

1. 게임마다 참여자 전원의 개인 순위를 0~100점으로 환산합니다.
2. 참여한 조원의 평균으로 조 순위를 정합니다. 인원이 달라도 공정합니다.
3. 판마다 1등 조 10점, 2등 조 7점, 3등 조 5점, 나머지 조 1점을 받습니다(`engine.ts`의 `TEAM_RANK_POINTS`, `TEAM_REST_POINTS`). 동점은 같은 등수·같은 점수이고, 참여자가 없는 조는 0점입니다.

개인 포인트와 조 점수는 따로 쌓입니다. 그래서 행사 끝에 **조 1등**과 **개인 전체 1등**을 각각 뽑을 수 있습니다. 게임마다 단위(회, m, 초)가 달라서, 개인 포인트는 게임 기록을 그대로 더하지 않고 순위를 0~100점으로 환산해 더합니다.

## 동시 접속

- 폰은 입력을 화면에 바로 반영하고 0.5초마다 묶어 보냅니다. 입력 시각을 함께 보내 순서가 밀리지 않습니다.
- 행사장 화면은 조 집계와 상위 10명만 초당 4회, 폰은 초당 1회 받습니다. 참가자가 늘어도 메시지 크기는 거의 늘지 않습니다.
- 이번 행사는 40명·5개 조 기준입니다. 관리자 화면의 기본 조 목록은 `games.json`의 `site.defaultTeams`에서 바꿉니다.
- 방당 상한은 500명(`MAX_PLAYERS`)입니다. Durable Object 한 개의 권장 처리량(초당 1,000건)에서 계산한 값으로, 운영 환경 부하 테스트는 아직 하지 않았습니다.

## 실시간 통신

- 화면 파일과 `/api/rooms`·`/api/dashboard`는 일반 HTTP이고, 게임은 `/api/rooms/방코드/ws` WebSocket으로 진행합니다.
- 개발 중에는 Next(3100)가 화면과 HTTP 전달을 맡고, WebSocket은 브라우저가 Worker(8797)로 직접 연결합니다. 운영에서는 Worker 하나가 같은 주소로 모두 처리합니다(`wss://`).
- 게임 판정과 단계 전환(알람)은 방 Durable Object가 담당해서 관리자 화면이 꺼져도 진행됩니다.
- 끊기면 `useRoom`이 자동으로 다시 연결하고, 참가자는 저장된 토큰으로 이어서 참여합니다.

## 실행

Node 24, pnpm 10이 필요합니다.

```bash
pnpm install
pnpm dev
```

- 화면 `http://localhost:3100`, Worker `http://localhost:8797` (meilian-wedding과 함께 띄울 수 있도록 포트를 나눴습니다).
- 로컬 관리자 비밀번호는 `local-admin`이며 `ADMIN_PASSWORD` 환경 변수로 바꿀 수 있습니다.
- 폰 테스트는 같은 와이파이에서 PC의 IP로 접속합니다. 흔들기·수평 잡기의 동작 센서는 HTTPS에서만 동작할 수 있습니다.

## 검증

```bash
pnpm lint
pnpm typecheck
pnpm build
pnpm simulate
```

`simulate`는 `pnpm dev`를 켠 상태에서 실행하며, 기본값은 40명·5개 조입니다(`--players=100 --teams=10`처럼 바꿀 수 있습니다). 입장 코드, 중복 닉네임, 재접속, 전체 게임, 점수 합계를 검사합니다. `--games=tap,race`로 일부만, `--mode=solo`로 개인전을 돌릴 수 있고, 끝나면 방을 닫습니다(`--keep`이면 남김). 자동 종료는 `ROOM_IDLE_MINUTES`를 짧게 둔 서버에 `--idle-wait=15`로 확인합니다. 운영 주소에 돌리면 Cloudflare 무료 한도를 쓰므로 횟수를 정해서 실행하세요.

## 배포

Windows PowerShell에서 이 폴더 기준으로 실행합니다.

```bash
pnpm check:deploy
pnpm exec wrangler secret put ADMIN_PASSWORD
pnpm run build
pnpm deploy:cloudflare
```

Secret을 등록하지 않으면 방을 만들 수 없습니다. 같은 Cloudflare 계정의 다른 Worker와 일일 요청 한도를 공유하므로, 행사 날에는 대시보드에서 사용량을 확인하세요.
